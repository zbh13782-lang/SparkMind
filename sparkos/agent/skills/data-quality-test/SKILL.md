# 数据质量测试

## 触发边界

- 用户必须同时要求“查询数据”和“质量测试/质量检查/数据质量检测”。
- 普通查询沿用查询流程，不追加测试 SQL、评分或质量报告。
- 用户仅询问质量维度、方法或定义时，只解释概念，不执行本流程。

## 执行顺序

1. 按 `data-catalog` 流程确认表、字段、分区与业务口径。
2. 先执行用户要求的业务查询，保留 SQL、过滤范围与结果。
3. 根据字段类型和业务语义选择适用的质量维度；不要为不适用维度编造规则。
4. 使用同一数据范围执行质量 SQL。优先把多个聚合指标合并到少量 Spark SQL 作业，异常样本另行限量查询。
5. 返回业务查询结果和质量报告，明确区分事实、阈值、假设与未验证项。

## 质量维度

| 维度 | 推荐指标 | 典型判定 |
|---|---|---|
| 完整性 | 总行数、空值数、空值率 | 必填字段空值率不超过阈值 |
| 唯一性 | 主键重复组数、重复行数、唯一率 | 主键重复数为 0 |
| 有效性 | 类型、格式、枚举、数值范围、日期范围违规数 | 违规率不超过阈值 |
| 一致性 | 跨字段规则、明细与汇总、跨表关联一致率 | 业务规则冲突数为 0 |
| 准确性 | 与权威值、计算规则或参考表比对的偏差 | 仅在存在可信参照时执行 |
| 及时性 | 最大业务时间、数据延迟、目标分区是否到达 | 延迟不超过约定 SLA |
| 完整覆盖 | 日期/分区缺口、维度成员缺失、预期范围覆盖率 | 无缺失分区或覆盖率达标 |
| 稳定性 | 行数、空值率、分布相对历史基线的变化 | 仅在存在历史基线时执行 |

默认至少测试：完整性、唯一性、有效性、及时性。若缺少主键、SLA、阈值、参考表或历史基线，将对应项标记为“未配置/未验证”，并展示实际测量值，不擅自宣告通过。

## SQL 模式

- 使用单次聚合计算总量、空值、范围违规、最大时间等指标。
- 唯一性按候选主键 `group by ... having count(*) > 1`，同时返回重复组数和受影响行数。
- 一致性使用条件聚合计算冲突数；跨表检查明确 Join Key，并报告未匹配率。
- 异常样本只查询必要字段并添加 `limit`，避免输出敏感或海量明细。
- 所有质量 SQL 使用与业务查询相同的日期、分区和业务过滤条件。

## 结果判定

每项结果使用以下状态：

- `通过`：有明确规则与阈值，实测满足要求。
- `不通过`：有明确规则与阈值，实测违反要求。
- `需关注`：出现明显异常，但用户未提供正式阈值。
- `未验证`：缺少字段、参考数据、历史基线或业务规则。

不要用任意默认分数掩盖缺失规则。需要汇总分时，只对已验证维度按等权计算通过率，并同时给出已验证项数量；存在关键项不通过时，总体结论不得为通过。

## 输出格式

1. **查询结果**：业务 SQL、范围、关键结果。
2. **质量概览**：总体结论、已验证项数、通过/不通过/需关注数量。
3. **维度明细**：维度、对象、规则/阈值、实测值、状态、证据。
4. **异常样本**：必要时给出限量样本或异常定位 SQL。
5. **改进建议**：只针对发现的问题给出优先级和可执行动作。
6. **未验证项**：列出缺少的主键、阈值、SLA、参照或基线。
